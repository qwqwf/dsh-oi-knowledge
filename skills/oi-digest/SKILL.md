# OI 题解消化（质量优先）

目标：每道题产出一句 `essence` 和 4–6 条洞察（observation / trick / idea / direction / pitfall），挂到思路树与观察树节点上。**先在本地抓好题面与题解，再派子代理读，主对话只看最终 JSON。**

## 质量优先（唯一标准）

质量只按「洞察是否真的讲清了做法」判断，不按「读了多少 token」判断：

1. **先切小节，再截断**：PDF 题解必须切出目标题那一节；只有切不出来时才整篇保留。
2. **截断必须显式标记**：摘要末尾带「…（已截断，原文 N 字）」。看到这个标记、且关键推导不在其中时，**对该题单独 `--tasks <key> --refetch`（不加 `--brief`）重读全文**，不设预算上限。
3. **宁可跳过，不许编**：题解缺失、切错题、或推导链明显不完整时，如实跳过并记录原因；绝不靠常识拼凑一个「看起来对」的精髓。
4. **数量按信息量**：每题 4–6 条，必须至少 1 条 observation + 1 条 direction；有多解法/多个关键跳跃的题可以更多。不为凑数写空话，也不为省字漏掉真正的难点。
5. **关键结论要验证**：能用样例、暴力小程序或极端数据对拍的，跑一下再写进洞察；验证过的在文字里注明「（已对拍/样例验证）」。
6. **不确定就说不确定**：推导链有缺口时，在洞察里写明「这里没完全想通」，不要伪装成确定结论。

## 铁律

1. 题面 + 题解合计在 1.3 万字符以内时**直接全文读**，不做压缩；只有明显超长（整场 PDF、几十道题的合集）才用 `--brief` 截掉与本题无关的正文。
2. 洞察必须写具体做法/公式/复杂度，禁止「用到 DP」「注意边界」这类空话；推不出就跳过，不编。
3. 写库走 `dev/digest-apply.mjs`（读 `dev/digest/out/batch-*.json`），写完必须重载插件：
   `plugin_manager action=set_plugin target=include:oi-knowledge enabled=false` 再 `=true`。
4. 派单前维护 in-flight 集合，避免重复派单（历史上出现过 q/u 完全重复）。
5. 子代理与主对话用同一个模型档位；**不要为了省钱换小模型**。

## 批量流程

1. 抓取：`& $node dev\atcoder-digest-fetch.mjs --min 2000 --max 2800 --limit 10`
   - 输出到 `dev/digest/inbox/<key>.txt`；已存在会跳过，`--refetch` 覆盖。
   - `--stats` 只看还剩多少题；`--tasks a,b` 只抓指定题。
   - 超长集合（整场 PDF）可以加 `--brief`，但记得看截断标记，必要时对单题重抓全文。
2. 派子代理：每个子代理 8–12 题，读 inbox + `dev/digest/node-list.md`，写 `dev/digest/out/batch-<x>.json`：
   ```json
   [{"key":"abc300_f","title":"F. ...","rating":2400,"essence":"一句具体精髓",
     "insights":[{"kind":"observation","text":"...","nodes":["节点名"]}]}]
   ```
   - `nodes` 只能取 `node-list.md` 里路径的**最后一段**；观察节点也可以挂。
   - 每题 4–6 条洞察，至少 1 条 observation + 1 条 direction。
   - 「（没有找到官方题解）」或题解切错题 → 跳过并在汇报里列出原因。
3. 写库：`& $node dev\digest-apply.mjs`（自动去重，已存在的跳过）。
4. 重载插件，抽检 `oi_kb action=show node="..."`，确认洞察按 kind 分组、节点挂载正确。
5. 汇报时列出：写了几道、跳过几道、跳过原因；不要只报成功数。

## 判断「精髓观察」

取解题时**最难想到/推导最长**的那一步，不是代码量或题面长度。典型：补集转化、贡献拆分、不变量、按位独立、建图归约、交换状态与决策、容斥、根号分层。
一道题可以有多条精髓观察（1–3 条），在 `oi_problem action=add_insight` 时给 `key: true`。

## 别做的事

- 不要把题面/题解原文大段贴进主对话；交给子代理读，主对话只收结论与理由。
- 不要为一道题反复重抓：先 `--stats`、再 `--tasks`。
- 不要在 apply 后忘记重载插件（插件进程会拿旧 kb 覆盖）。
